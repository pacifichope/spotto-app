# 主催者・売上管理の動作確認手順（開発用）

`__DEV__` ビルドでは次が有効です（`lib/devTestFlags.ts`）:

- 過去日付でのイベント作成（日付ピッカーで最大 60 日前まで）
- 終了済みイベントへの参加・決済
- 売上管理画面の「テスト売上を記録」（1 アカウントで集計確認）

## A. 過去イベントを作成する

1. 主催者アカウントでログイン
2. イベント作成を開き、参加費を有料（例: 1,000 円）に設定
3. 開催日時で **昨日** や **先週** を選んで公開
4. マイページの「開催したイベント（過去）」などに表示されることを確認

## B. 決済 → 売上反映（推奨: 2 アカウント）

1. 別の参加者アカウントでログインし、その過去イベントを開く
2. Join → Stripe テスト決済（またはデモ決済）を完了
3. 主催者アカウントで **設定 → 売上管理** を開く
4. 月送りで **イベント開催日の月** を選び、売上・手取り・「振込待ち（確定）」を確認

集計は開催日ベースです。昨日開催なら当月、先月なら前月に出ます。

## C. 1 アカウントだけの場合

1. A で過去の有料イベントを作成
2. 別途 SQL（`supabase/seed_sales_qa.sql`）でテスト売上を差し込むか、2アカウントで参加者決済する
3. 主催者で **設定 → 売上管理** を開き、該当月のサマリー・内訳を確認

主催者は自分のイベントに Join できないため、1 アカウントでは SQL シードか 2 アカウント決済が必要です。

## D. SQL で台帳だけ差し込む（任意）

アプリを使わず DB に直接入れる場合は `supabase/seed_sales_qa.sql` を参照し、
`HOST_ID` / `EVENT_ID` / `BUYER_ID` を実値に置き換えて実行してください。

## 判定のポイント

| 項目 | 期待 |
| --- | --- |
| 過去イベントのステータス | `isEventPast` → 開催終了（マイページ過去枠） |
| 確定売上 | `event_ends_at`（または開催日 23:59:59 JST）が現在以前 → 振込待ち（確定） |
| 未確定 | 未来開催の売上が「開催待ち」 |
| 手取り | 確定売上 − 決済手数料3.6% − 利用料10% − 振込手数料 500 円 |

## E. 運営の振込確認（DB）

アプリ内に管理者画面はありません。振込対象の確認は Supabase SQL Editor で
`supabase/admin_payouts_report.sql` を実行し、`year_month` を書き換えてください。
